# QMES 안정화 정리 계획 (2026-08-05)

## 작업 원칙
- 화면과 기능을 한 번에 제거하지 않는다.
- 원본 JSX/CSS에 기능을 옮긴 뒤 같은 역할의 보정 스크립트를 제거한다.
- 한 메뉴씩 적용하고 등록, 수정, 삭제, 새로고침, 인쇄, 연동을 확인한다.
- 각 단계는 독립 커밋으로 남겨 즉시 되돌릴 수 있게 한다.

## 현재 확인된 구조

### 원본 화면
- 거래처 관리: `public/js/partners.jsx`
- 설비 관리 및 일일점검: `public/js/ipad-pop.jsx`
- LOT 추적: `public/js/lot.jsx`, `public/js/charts.jsx`
- 작업지시: `public/js/production.jsx`
- 검사: `public/js/iqc.jsx`, `public/js/pqc.jsx`, `public/js/oqc.jsx`
- 공용 동기화: `public/js/qmes-sync.js`

### 후처리/보정 스크립트
- `public/js/table-and-equipment-spacing-20260805.js`
- `public/js/equipment-layout-refinement-20260805.js`
- `public/js/partner-equipment-fix-20260805.js`
- `public/js/qmes-ui-refinement-20260805.js`
- `public/js/lot-detail-alignment-20260805.js`
- 기타 작업지시·출하성적서·LOT 상태 보정 스크립트

## 정리 순서

### 1단계: 거래처 관리
- 검색창, 돋보기, 등록 버튼 배치를 `partners.jsx` 원본에 반영
- 탭과 목록 카드 사이 간격을 원본에 반영
- 테이블 가운데 정렬과 패딩을 원본에 반영
- 적용 확인 후 거래처 관련 DOM 보정 코드를 제거

### 2단계: 설비 관리
- 메뉴 탭 크기와 간격을 원본에 반영
- 신규등록 버튼 세로 정렬을 원본에 반영
- 설비대장·정기점검·고장수리 표 정렬을 원본에 반영
- 현황 카드 위 중복 구분선을 원본 구조에서 제거
- 적용 확인 후 설비 관련 DOM 보정 코드를 제거

### 3단계: LOT 추적
- 검색영역 크기, 상세 탭 정렬, 생산실적 표시를 원본에 반영
- 원재료/생산/공정/출하 데이터 연결 키를 점검
- 출하상태 보정 스크립트 의존성을 줄이고 원본 데이터 계산으로 전환

### 4단계: 품질검사·출하성적서
- 미리보기/인쇄 경로 점검
- 제조일·출하번호 테두리 보정을 인쇄 CSS 원본에 통합
- 출력용 후처리 스크립트 중복 제거

### 5단계: 부적합 관리
- 수정/조치완료 버튼 흐름과 상태변경 확인
- 삭제/조치 이력 및 LOT 연결 확인
- 다른 PC와 서버 동기화 범위 확인

### 6단계: 동기화 및 회귀 점검
- IQC/PQC/OQC/작업지시/설비 서버 동기화 확인
- 거래처/LOT/부적합의 로컬·서버 저장 범위 명확화
- 같은 키 동시 수정 충돌과 삭제 tombstone 필터 확인
- 메뉴 이동, 새로고침, 등록, 수정, 삭제, 인쇄 체크리스트 수행

## 1단계 확인 사항
`partners.jsx`는 현재 고객사/공급업체와 원료 LOT를 로컬 DB에 저장하고, 빈 작업지시 원료 LOT에 자동 반영한다. 거래처 화면의 최근 배치·간격 변경은 별도 DOM 보정 스크립트가 담당하고 있으므로, 다음 커밋에서 이 UI를 원본 JSX/CSS로 이동한다.
